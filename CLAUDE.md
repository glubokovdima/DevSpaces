# DevSpaces

Боковая панель справа для Windows 11 в духе Stage Manager: карточки виртуальных рабочих столов с миниатюрами, клик — переход на стол. Для себя (один пользователь). Как должно работать — `SPEC.md`. План и сделанное — `TODO.md`. Описание для страницы GitHub — `README.md`.

Документы клиента: нет (проект для себя).

## Стек и запуск

- Python 3.13 (поставлен через `py install 3.13`), PySide6 6.12, pyvda 0.6, mss 10.2, PyInstaller 6.22. Версии — `requirements.txt`.
- Проект живёт **на Windows** (`D:\soft\DevSpaces`), не в WSL: ему нужен Win32 и рабочий стол. Все команды — из Windows.
- Окружение: `.venv` (`py -3.13 -m venv .venv`, затем `.venv\Scripts\pip install -r requirements.txt`).
- Запуск из исходников: `run.bat` (то же: `.venv\Scripts\pythonw.exe devspaces.py`; с консолью — `python.exe`).
- Сборка EXE: `build.bat` → `dist\DevSpaces.exe` (один файл, ~49 МБ, без консоли).
- Перед запуском из исходников закрыть `DevSpaces.exe` (трей → Выход или `taskkill /F /IM DevSpaces.exe`): второй экземпляр молча выходит по lock-файлу.
- Данные: `%APPDATA%\DevSpaces\` — `settings.json`, `devspaces.log` (все события пишутся сюда), `devspaces.lock`.
- Проверено на Windows 11 26H2 сборка 26300, основной монитор 2560×1440 @125 %, второй монитор справа.

## Устройство (`devspaces.py`, один файл)

- `Capturer` — снимок основного монитора (mss) в фоновом потоке + `grab_now` синхронно перед переключением.
- `LiveComposer` — миниатюры неактивных столов: обои + окна стола через `PrintWindow` + панель задач с текущего экрана, фоновый поток.
- `Card` — карточка: плоская картинка рендерится в pixmap, перспектива (`QTransform.rotate` по оси Y) и увеличение при наведении — при отрисовке.
- `Panel` — прозрачное окно со списком карточек и анимацией выезда; `Handle` — полоска-ручка у края, прозрачная для мыши.
- `DevSpaces` — таймеры: текущий стол 300 мс, список столов 1 с, список приложений 2 с, мышь и перекрытие окном 50 мс, снимок 1 с, живые миниатюры — проверка раз в 5 с.
- Настройки внешнего вида и таймингов — константы в начале файла (`THUMB_W`, `CARD_TILT`, `HOVER_SCALE`, `LIVE_EVERY`, `HOT_W`/`HOT_H` и др.).

## Правила кода (Python)

- Окружение — `.venv` проекта. В системный Python ничего не ставить.
- Один файл, пока он не стал большим. Без слоёв «на вырост».
- Win32 — через `ctypes` прямо в файле; у функций с указателями задавать `restype`/`argtypes` (`GetWindowLongPtrW` на 64 бит).
- Комментарии — только «почему».
- Кириллицу и длинные тексты в скрипты передавать файлами, не аргументами командной строки.

## Подводные камни (проверено)

- **Закрепление на всех столах.** pyvda (`AppView(hwnd).pin()`) не видит окна без ApplicationView: с `Qt.Tool` или `WS_EX_NOACTIVATE` — ошибка «Элемент не найден». Поэтому `Panel` создаётся обычным frameless + topmost окном, закрепляется, и только потом `apply_panel_styles` ставит `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` (нет в Alt+Tab, не забирает фокус). Не добавлять `Qt.Tool`/`WindowDoesNotAcceptFocus` в флаги `Panel`. Окна-инструменты без ApplicationView Windows и так не прячет при смене стола; на случай сбоя есть запасной вариант — показать окно заново, если его спрятали (`poll_current`).
- **Панель исключена из любых снимков** (`SetWindowDisplayAffinity` `WDA_EXCLUDEFROMCAPTURE`), поэтому скриншот для проверки вида её не покажет. Для проверки: `set DEVSPACES_NO_EXCLUDE=1` перед запуском из исходников. `PrintWindow` нашей прозрачной панели даёт чёрное.
- **Несколько мониторов с разным масштабом.** В логических координатах Qt между экранами разрыв (основной 0…2048, второй с 2560). Любые проверки «у края» ограничивать геометрией основного экрана, иначе второй экран целиком считается «краем» (был баг с миганием).
- **mss** — свой экземпляр на каждый поток (в главном — `Capturer._main_mss`).
- Окно `Handle` получает hwnd только после первого `show()` — `FindWindowW("DevSpaces Handle")` до этого вернёт 0.
- `PrintWindow(..., 2)` (`PW_RENDERFULLCONTENT`) отдаёт содержимое окон неактивного стола (VS Code, Chrome, Telegram, Terminal, WhatsApp — проверено). Невидимые рамки окна рисует чёрным — рисуем только `DWMWA_EXTENDED_FRAME_BOUNDS`.
- Автотесты двигают настоящую мышь: если пользователь в это время трогает мышь, результаты врут. `SetForegroundWindow` из теста Windows иногда не разрешает — проверять `GetForegroundWindow()` в тесте.

## Тесты и проверки (`tools/`)

- `check_vda.py` — pyvda видит столы, текущий стол и окна (только чтение).
- `probe_printwindow.py` — какие окна неактивных столов отдают картинку через `PrintWindow` (только чтение).
- `e2e_smart.py` — живой тест умного режима: тестовое окно развернуть/сдвинуть, ручка, клик по 2-й карточке, снимок перед переключением. Запускать при работающем `devspaces.py`/EXE, мышь не трогать ~15 с; переключает столы.

## Нельзя

- Docker и любые контейнеры.
- Создавать, удалять и переименовывать рабочие столы пользователя без просьбы.
- Сохранять снимки экрана на диск без решения пользователя (сейчас только в памяти).
